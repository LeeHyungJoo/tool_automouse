# tool_automouse

Windows 10/11용 C++17 MFC 시스템 트레이 오토클릭 앱입니다. 실행하면 창 대신 트레이 아이콘이 표시되며, 다른 프로그램을 사용하는 동안에도 단축키로 제어할 수 있습니다.

## 빌드

필요한 개발 환경:

- Windows 10/11
- Visual Studio 2022의 **C++를 사용한 데스크톱 개발** 워크로드
- 개별 구성 요소 **최신 v143 빌드 도구용 C++ MFC(x86 및 x64)**
- Windows 10 또는 11 SDK

`AutoClicker.sln`을 열고 **Release / x64**를 선택한 다음 솔루션을 빌드합니다. 결과 파일은 `bin\x64\Release\AutoClicker.exe`입니다. MFC와 C/C++ 런타임은 정적으로 링크하도록 설정했습니다.

Visual Studio의 Developer Command Prompt에서도 빌드할 수 있습니다.

```bat
msbuild AutoClicker.sln /m /p:Configuration=Release /p:Platform=x64
```

Win32 빌드는 `/p:Platform=Win32`를 사용합니다.

GitHub Actions의 **Build and test** 워크플로는 Linux 핵심 테스트와 Windows x64·Win32 Release 빌드를 수행합니다. 성공한 실행의 **Artifacts**에서 `AutoClicker-Windows-x64` 또는 `AutoClicker-Windows-Win32`를 내려받으면 실행 파일을 사용할 수 있습니다. PR, `main` 브랜치 push, 수동 실행을 지원합니다.

## 사용 방법

1. `AutoClicker.exe`를 실행합니다. 트레이의 숨겨진 아이콘 영역(`^`)에 있을 수도 있습니다.
2. 클릭할 위치에 마우스 포인터를 놓습니다.
3. **Alt와 C를 누른 상태에서 P**를 눌러 시작합니다. 지정 간격을 한 번 기다린 뒤, 시작 키를 모두 놓은 상태에서 해당 좌표의 왼쪽 버튼 클릭을 반복합니다.
4. **Alt와 C를 누른 상태에서 S**를 눌러 정지합니다. 앱이 백그라운드에 있어도 동작합니다.
5. 트레이 아이콘을 우클릭하면 **설정(Settings)**, **정지**, **종료(Exit)** 메뉴가 나타납니다. 설정창을 열거나 트레이 메뉴를 열면 클릭은 정지합니다. 종료는 아이콘과 입력 훅, 작업 스레드를 정리한 후 프로세스를 종료합니다.

`Alt+C+P`, `Alt+C+S`는 세 키를 함께 누르는 조합입니다. C를 놓은 다음 P/S를 누르는 순차 입력이 아닙니다. 시작 위치는 시작할 때 한 번 저장되며, 포인터를 옮겨도 저장한 좌표를 계속 클릭합니다. 실행 중 시작 단축키를 다시 눌러도 별도의 클릭 작업을 중복 생성하지 않습니다. Ctrl·Shift·Windows 키가 함께 눌린 조합은 단축키로 처리하지 않습니다.

클릭 실행 중 Alt·Ctrl·Shift·Windows 키를 누르거나 마우스 왼쪽 버튼으로 드래그하는 동안에는 클릭을 건너뜁니다. 디스플레이 구성이 바뀌면 클릭을 정지합니다.

단축키를 감지한 P/S 입력은 차단하지만, 먼저 누른 Alt+C는 활성 프로그램에도 전달됩니다. 해당 프로그램이 Alt+C 메뉴나 단축키를 사용하면 반응할 수 있습니다.

## 클릭 간격 설정

트레이 **설정(Settings)**에서 값을 입력하고 **적용**을 누릅니다.

| 단위 | 입력 예시 | 실제 간격 |
|---|---|---|
| 밀리초(ms) | `100` | 100 ms |
| 초(s) | `0.25` | 250 ms |
| 초(s) | `1.5` | 1,500 ms |

- 기본값: **1,000 ms(1초)**
- 허용 범위: **1~3,600,000 ms(최대 1시간)**
- 밀리초는 정수로 입력합니다. 초는 소수점 `.`을 사용하며 소수 셋째 자리까지 입력할 수 있습니다.
- 빈 값, 0, 음수, 범위 초과 값, 지원하지 않는 소수 정밀도는 저장하지 않습니다.
- **닫기**는 입력 중인 변경을 저장하지 않습니다.
- 설정은 현재 사용자 레지스트리 `HKEY_CURRENT_USER\Software\MfcAutoClicker\Settings` 아래에 저장되어 다음 실행에도 유지됩니다.
- 설정을 적용한 뒤 시작 단축키를 눌러 다시 실행합니다.

Windows의 스레드 스케줄링과 시스템 부하 때문에 실제 간격에는 오차가 있습니다. 1 ms 설정은 1 ms마다의 정확한 클릭을 보장하지 않습니다. 관리자 권한으로 실행 중인 창은 Windows 입력 보안 정책(UIPI)에 따라 일반 권한 앱의 클릭 입력을 받지 않을 수 있습니다.

Windows 잠금·세션 연결 해제·절전 시 클릭과 단축키 훅을 중단합니다. 사용 가능한 상태로 돌아오면 키 상태를 새로 읽어 단축키 훅을 복구하며, 자동 클릭은 시작 단축키를 다시 눌러야 재개됩니다.

## 구현 구조

| 파일 | 역할 |
|---|---|
| `AutoClicker/App.*` | MFC 앱 초기화, 설정 저장 위치, 단일 인스턴스 관리 |
| `AutoClicker/TrayWindow.*` | 숨겨진 창, 트레이 메뉴, 클릭 시작/정지, 세션 및 전원 이벤트 |
| `AutoClicker/GlobalHotkeys.*` | 전역 `WH_KEYBOARD_LL` 훅과 명령 전달 |
| `AutoClicker/ClickEngine.*` | 중단 가능한 대기와 `SendInput` 기반 클릭 |
| `AutoClicker/SettingsDialog.*` | 입력 검증과 설정 GUI |
| `AutoClicker/Core/*` | 플랫폼 독립 단축키 상태 및 간격 검증 |

`RegisterHotKey`는 modifier+일반 키 하나 형태를 지원하므로 Alt와 일반 키 두 개의 조합을 그대로 등록할 수 없습니다. 이 앱은 저수준 키보드 훅으로 키 상태를 추적하고, 감지한 시작/정지 명령을 창 메시지로 전달합니다. 클릭 처리는 훅 콜백 밖에서 수행합니다.

## 검증

개발 환경은 Linux입니다. 단축키 상태·간격 파서 테스트와 실제 클릭 엔진의 모의 Win32 API 테스트, 프로젝트 파일 정합성 검사를 통과했습니다. Windows 컴파일은 GitHub Actions에서 x64·Win32 구성으로 확인하며, **실제 Windows GUI·전역 훅·입력 전달은 수동 검증이 필요합니다**. `tests` 폴더의 테스트는 MFC 앱 빌드에 포함되지 않습니다. Linux에서 `bash tests/run_portable.sh`로 재실행할 수 있으며, 자세한 내용은 `tests/README.md`를 참고하십시오.

Windows에서 빌드 후 다음 항목을 확인하십시오.

- 실행 직후 작업표시줄 창 대신 트레이 아이콘이 표시되는지
- 메모장 등 다른 창이 활성화된 상태에서도 두 단축키가 동작하는지
- 시작 키를 계속 누르거나 다시 눌러도 작업이 중복 실행되지 않는지
- 클릭 위치와 횟수를 확인할 수 있는 테스트 창에서 지정 간격대로 클릭되는지
- 정지 후 다음 예정 클릭을 기다리지 않고 멈추는지
- ms와 초 입력, 잘못된 값 거부, 종료 후 재실행 시 설정 복원이 동작하는지
- 여러 모니터 및 음수 좌표에서 시작 좌표가 맞고, 디스플레이 변경 시 클릭이 멈추는지
- 설정창, 트레이 메뉴, Windows 잠금 및 절전 시 클릭이 멈추는지
- Explorer를 다시 시작하면 트레이 아이콘이 복원되는지
- 트레이 **종료(Exit)** 후 프로세스가 남지 않는지
